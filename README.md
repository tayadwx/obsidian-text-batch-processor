# Obsidian 文本批处理插件（Text Batch Processor）

一个本地运行的 Obsidian 插件：对**选中的文本**执行预设或自定义的处理动作，并可以把多个动作**自由组合成序列**保存复用。

核心理念：**动作 = 你自己写的一段 JavaScript 代码**。插件在运行时编译执行这段代码，因此功能可以无限扩展——你不需要改插件源码，只要会写（或让 AI 帮你写）一小段文本处理代码即可。

> ⚠️ 安全提示：动作代码以你的身份在本地直接执行（`new Function` 编译运行），**只运行你自己写的、可信的代码**。不要把来源不明的动作代码加进插件。

---

## 功能特性

- **自定义动作**：为动作命名，并编写一段 JS 代码（函数体），代码接收输入文本 `text`，必须 `return` 处理后的字符串。
- **可组合序列**：把多个动作按顺序排列成一个序列，执行时像流水线一样依次处理（上一个动作的输出作为下一个的输入）。
- **多种触发方式**：
  - 桌面端：选中文本 → 右键「文本批处理」→ 弹出选择框，点选动作/序列即可执行。
  - 命令面板：每个动作、每个序列都会注册成一条命令，可在命令面板搜索调用。
  - 快捷键：在 Obsidian 设置里给任意动作/序列命令绑定快捷键。
  - 移动端：把命令加入移动端工具栏，触屏一点即执行。
- **常用置顶**：动作和序列都能标记为「常用」，在弹出选择框和命令里带 ★ 置顶显示，实现一键直达。
- **按钮式序列构建器**：在设置页的序列编辑里，用**下拉选择器**把已有动作加为步骤（选中即自动添加），再用「上移 / 下移 / 删除」调整顺序。
- **纯本地、无后端**：所有配置保存在插件的 `data.json` 中，不上传任何服务器。

## 安装

### 方式一：通过 BRAT（推荐，适合持续更新）

1. 在 Obsidian 社区插件市场安装 **BRAT**（Beta Reviewers Auto-update Tool）。
2. 打开 BRAT 设置 → `Add a beta plugin`。
3. 输入仓库地址：`tayadwx/obsidian-text-batch-processor`
4. 启用「文本批处理」插件。

> BRAT 依赖 GitHub Release。若手动更新，请在仓库打一个与 `manifest.json` 中 `version` 一致的 Release（如 `1.1.0-beta1`），并在 Release 的附件里上传 `manifest.json`、`main.js`、`styles.css`。**版本号含 `-`（如 `1.1.0-beta1`）会被标记为预发布（Pre-release），适合 BRAT 测试用户抢先体验。**

### 方式二：手动安装

1. 从仓库的 Release（或根目录）下载三个文件：`manifest.json`、`main.js`、`styles.css`。
2. 放到你的仓库目录：`<你的仓库>/.obsidian/plugins/text-batch-processor/`
3. Obsidian 设置 → 第三方插件 → 关闭安全模式 → 启用「文本批处理」。

## 使用流程

### 1. 增加动作

1. 打开 Obsidian 设置 → 第三方插件 → 文本批处理 → 选项。
2. 在「动作管理」区点 **+ 新增动作**。
3. 填写：
   - **名称**：例如「标题降级为普通文本」。
   - **代码**：编写处理文本的函数体（见下文「动作代码写法」）。
4. 点保存即生效。

### 2. 组合序列

1. 在设置页的「序列」区点 **+ 新增序列**。
2. 命名序列，例如「清理标题与空行」。
3. 在下方的动作下拉里选一个已有动作，**选中即自动添加为步骤**，再用 **上移 / 下移 / 删除** 调整顺序。
4. 调整后点「保存」即可生效（取消则放弃本次编辑）。

### 3. 调用动作或序列

- **桌面端右键**：选中文本 → 右键「文本批处理」→ 弹出选择框 → 点击要执行的动作/序列（标了常用的带 ★ 排在最前）。
- **命令面板**：打开命令面板（默认 `Ctrl/Cmd + P`），搜索动作或序列名称。
- **快捷键**：设置 → 快捷键 → 搜索「文本批处理」相关命令并绑定。
- **移动端**：设置 → 移动端 → 把对应命令加到工具栏。

## 动作代码写法

你写的代码会被当作一个**函数体**执行，等价于：

```js
function (text) {
  // 你写的代码在这里
}
```

- 可用变量：**`text`**（输入的字符串，即你选中的文本）。
- **必须 `return` 一个字符串**，否则会提示「动作未返回字符串」。
- 语法就是标准 JavaScript（和 Python 控制流类似，正则写法略有差异）。

### 内置示范动作

插件预置了两个示范动作和一个示范序列，方便你直接体验。

**动作①：标题降级为普通文本**（去掉行首的 `#` 与空格）

```js
// 把选中文本里所有 Markdown 标题降级为普通文本
// 即：去掉行首的若干 "#" 和一个空格
return text.replace(/^#+\s+/gm, '');
```

**动作②：去除多余空行**（连续空行 / 纯半角或全角空格行，合并为单个空行）

```js
// 去除多余的空行：连续多个空行（或纯空格/全角空格行）合并为一个空行
const lines = text.split('\n');
const out = [];
let prevBlank = false;
for (const line of lines) {
  const isBlank = /^[　\s]*$/.test(line);
  if (isBlank) {
    if (!prevBlank) out.push('');
    prevBlank = true;
  } else {
    out.push(line);
    prevBlank = false;
  }
}
return out.join('\n');
```

**示范序列**：`动作① + 动作②` —— 先把所有标题降级，再收敛多余的空行，一键得到干净的纯文本块。

你可以直接复制上面的代码去建自己的动作，或以此为基础改写。

## 错误处理

- 动作代码若运行抛错：插件会弹 `Notice` 提示错误，**不会修改你的原文**。
- 若动作没有 `return` 字符串：会提示「动作未返回字符串」，原文保持不变。

## 目录结构与开发

```
.
├── manifest.json          # 插件元信息（名称/版本/入口）
├── main.js                # 构建产物（由 src/ 编译而来，插件真正运行的文件）
├── styles.css             # 样式
├── src/                   # TypeScript 源码
│   ├── main.ts            # 入口：注册命令、右键菜单、选区处理
│   ├── actions.ts         # 编译用户代码、执行序列（流水线）
│   ├── settings.ts        # 设置页：动作管理 + 序列构建器
│   ├── picker.ts          # 「选择动作/序列」弹窗（常用置顶 + 模糊搜索）
│   └── types.ts           # 数据结构 + 示范动作/序列默认代码
├── esbuild.config.mjs     # 构建配置（esbuild）
├── tsconfig.json
├── package.json
└── scripts/deploy.mjs     # 仅本地用：把核心文件复制到测试仓库（不进仓库）
```

本地开发命令：

```bash
npm install        # 安装依赖
npm run dev        # 开发模式，监听改动热更新（仍需 BRAT/重启插件生效）
npm run build      # 构建出 main.js
npm run deploy     # 仅本地：把 manifest.json/main.js/styles.css 复制到测试仓库
                    # （默认复制到本机测试仓库的插件目录，详见 scripts/deploy.mjs 中的 dest，不会覆盖 data.json）
```

> `scripts/deploy.mjs` 仅用于本地测试部署，已加入 `.gitignore`，不会进入公开仓库。

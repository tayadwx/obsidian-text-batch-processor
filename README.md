# Obsidian 文本批处理插件（Text Batch Processor）

> 把「你常用的文本整理操作」存成可复用的按钮，多个按钮串成一条流水线，选中文本一键出结果。

---

## 这个插件能帮你解决什么？

你有没有在 Obsidian 里反复做这些事：

- 需要定期对某些工作日志文件按照特定方式进行处理;
- 从网页复制来一坨杂乱文本，要整理成干净的结构存放到笔记里；
- 给word复制过来的文字按照个性化的需求转换成markdown格式；
- 统一中英标点、给列表加序号、批量改大小写、提取所有链接；
- 按某种规则重排段落、清理多余空行、给每段加固定前缀……

这些活儿，**手动做烦，让AI来做又有点费token，写一次性脚本又太重，现成插件功能一般是写死的不能灵活自定义**。

本插件的解法是：**动作 = 你自己写（或让 AI 写）的一段 JavaScript 代码**。插件在本地编译执行这段代码，对选中的文本做处理。你不受插件作者预设功能的限制——你能想到的文本变换，基本都能写成一个动作。

核心能力：

- **自定义动作**：一个动作就是一段 JS 函数体，接收 `text`，`return` 处理后的字符串。想怎么改文本都行。
- **可组合序列**：把多个动作按顺序排列成序列，执行时像流水线一样依次处理（上一动作的输出是下一动作的输入）。
- **多种触发**：右键菜单、命令面板、快捷键、移动端工具栏，任选其一或全要。
- **不会写代码也没关系**：内置一份「给 AI 的提示词」，你只需把提示词 + 你的需求发给任意网页 Chat AI，它直接吐出一份**可导入的 JSON**（见下方实战案例）。导入即用，无需懂 JS。
- **纯本地、可分享**：所有配置存在本机 `data.json`，不上传服务器；动作/序列可导出成 JSON 分享给他人或跨设备同步。

一句话真实案例：**从 B站 复制的一坨杂乱评论 → 选中 → 运行一个序列 → 变成「用户名：（时间）内容（点赞数：452）」的标准格式。** 整个过程不需要你写一行代码。

> ⚠️ 安全提示：动作代码以你的身份在本地直接执行（`new Function` 编译运行），**只运行你自己写的、或你信任来源的、可信的代码**。不要把来源不明的动作代码加进插件。

## 30 秒快速体验

如果你只是想马上用上，跟着做：

1. 安装插件（见下方「安装」）。
2. 打开一份现成的示范包（仓库 `starter/` 目录，或 README 实战案例里的 AI 生成 Pack）——设置 → 文本批处理 → 选项 → 导入配置 → 选本地 `.json` 文件。
3. 在任意笔记里选中一段文本，右键 → 「文本批处理」→ 点你刚导入的序列，结果立即替换选中内容。如果不选择文本直接运行，则会处理整个文件的文本。

想自己造动作？往下看「动作代码写法」；想让 AI 帮你造？看「实战案例：用 AI 生成你的专属动作」。

## 功能特性

- **自定义动作**：为动作命名，并编写一段 JS 代码（函数体），代码接收输入文本 `text`，必须 `return` 处理后的字符串。
- **可组合序列**：把多个动作按顺序排列成一个序列，执行时像流水线一样依次处理（上一个动作的输出作为下一个的输入）。
- **多种触发方式**：
  - 桌面端：选中文本 → 右键「文本批处理」→ 弹出选择框，点选动作/序列即可执行。
  - 命令面板：每个动作、每个序列都会注册成一条命令，可在命令面板搜索调用。
  - 快捷键：在 Obsidian 设置里给任意动作/序列命令绑定快捷键。
  - 移动端：把命令加入移动端工具栏，触屏一点即执行。
- **常用置顶**：动作和序列都能标记为「常用」，在弹出选择框和命令里带 ★ 置顶显示，实现一键直达。
- **按钮式序列构建器**：在设置页的序列编辑里，用**下拉选择器**把已有动作加为步骤（选中即自动添加），再用「上移 / 下移 / 删除」调整顺序。
- **纯本地、无后端**：所有配置保存在插件的 `data.json` 中，不上传任何服务器。

## 安装

### 方式一：通过 BRAT（推荐，适合持续更新）

1. 在 Obsidian 社区插件市场安装 **BRAT**（Beta Reviewers Auto-update Tool）。
2. 打开 BRAT 设置 → `Add a beta plugin`。
3. 输入仓库地址：`tayadwx/obsidian-text-batch-processor`，选择一个版本安装。
4. 启用「文本批处理」插件。


### 方式二：手动安装

1. 从仓库的 Release（或根目录）下载三个文件：`manifest.json`、`main.js`、`styles.css`。
2. 放到你的仓库目录：`<你的仓库>/.obsidian/plugins/text-batch-processor/`
3. Obsidian 设置 → 第三方插件 → 关闭安全模式 → 启用「文本批处理」。

## 使用流程

### 1. 增加动作

1. 打开 Obsidian 设置 → 第三方插件 → 文本批处理 → 选项。
2. 在「动作管理」区点 **+ 新增动作**。
3. 填写：
   - **名称**：例如「标题降级为普通文本」。
   - **代码**：编写处理文本的函数体（见下文「动作代码写法」）。
4. 点保存即生效。

### 2. 组合序列

1. 在设置页的「序列」区点 **+ 新增序列**。
2. 命名序列，例如「清理标题与空行」。
3. 在下方的动作下拉里选一个已有动作，**选中即自动添加为步骤**，再用 **上移 / 下移 / 删除** 调整顺序。
4. 调整后点「保存」即可生效（取消则放弃本次编辑）。

### 3. 调用动作或序列

- **桌面端右键**：选中文本 → 右键「文本批处理」→ 弹出选择框 → 点击要执行的动作/序列（标了常用的带 ★ 排在最前）。
- **命令面板**：打开命令面板（默认 `Ctrl/Cmd + P`），搜索动作或序列名称。
- **快捷键**：设置 → 快捷键 → 搜索「文本批处理」相关命令并绑定。
- **移动端**：设置 → 界面 → 设置移动端工具栏 → 添加命令（文本批处理：选择动作或序列）或是 更多工具栏选项：把对应命令加到工具栏。

## 动作代码写法

你写的代码会被当作一个**函数体**执行，等价于：

```js
function (text) {
  // 你写的代码在这里
}
```

- 可用变量：**`text`**（输入的字符串，即你选中的文本）。
- **必须 `return` 一个字符串**，否则会提示「动作未返回字符串」。
- 语法就是标准 JavaScript（和 Python 控制流类似，正则写法略有差异）。

### 内置示范动作

插件预置了两个示范动作和一个示范序列，方便你直接体验。

**动作①：标题降级为普通文本**（去掉行首的 `#` 与空格）

```js
// 把选中文本里所有 Markdown 标题降级为普通文本
// 即：去掉行首的若干 "#" 和一个空格
return text.replace(/^#+\s+/gm, '');
```

**动作②：去除多余空行**（连续空行 / 纯半角或全角空格行，合并为单个空行）

```js
// 去除多余的空行：连续多个空行（或纯空格/全角空格行）合并为一个空行
const lines = text.split('\n');
const out = [];
let prevBlank = false;
for (const line of lines) {
  const isBlank = /^[　\s]*$/.test(line);
  if (isBlank) {
    if (!prevBlank) out.push('');
    prevBlank = true;
  } else {
    out.push(line);
    prevBlank = false;
  }
}
return out.join('\n');
```

**示范序列**：`动作① + 动作②` —— 先把所有标题降级，再收敛多余的空行，一键得到干净的纯文本块。

你可以直接复制上面的代码去建自己的动作，或以此为基础改写。

## 动作与序列开发指南

本插件的核心是「自己写代码的动作」+「把动作拼成序列」。下面从零讲清：如何写动作、如何组合序列，以及如何把成果整理成一份**可被插件直接导入的 JSON**（人和 AI 都能读、能改、能分发）。

### 1. 编写动作（自定义代码）

动作就是一段 **JavaScript 函数体**。插件在运行时用 `new Function('text', code)` 编译并执行：

```js
function (text) {
  // 你写的代码，最后必须 return 字符串
}
```

规则与约定：
- 输入变量 **`text`**（字符串）：你选中的文本；无选区时为整篇文档内容。
- **必须 `return` 一个字符串**；返回非字符串会提示「动作未返回字符串」，原文保持不变。
- 可使用标准 JavaScript 全部能力（`String` / `Array` / `RegExp` 等）。
- 代码抛异常时，插件弹 `Notice` 提示错误，**不修改原文**。

调试建议：先在设置里建一个动作，用一小段选中文本反复试；或先在浏览器控制台 / Node 里把逻辑跑通，再粘进来。

进阶示例：
- 行首加序号：`return text.split('\n').map((l, i) => (i + 1) + '. ' + l).join('\n');`
- 英文标点转中文：`return text.replace(/,/g, '，').replace(/\./g, '。').replace(/;/g, '；');`
- 统计字数并附到文末：`const n = [...text].length; return text + '\n\n字数：' + n;`

> 更完整的示范（标题降级、去空行等）见上文「动作代码写法」。

### 2. 组合序列（流水线）

序列 = 若干动作的**有序列表**，执行时像流水线一样依次处理：

```
输入文本 → 动作A → 动作B → … → 输出文本
```

- 上一个动作的返回值，自动作为下一个动作的 `text` 输入。
- 步骤**顺序**决定结果；在设置里用「上移 / 下移」调整即可。
- 同一动作可被多个序列复用；把序列设为「常用」后，右键菜单可一键调用。

组合思路：把可复用的小动作（如「去空行」「转小写」）拆细，再用序列拼成不同流水线，避免重复造轮子。

### 3. 导出 / 导入 JSON

插件内置「导出 / 导入配置」：
- **导出**：把当前全部动作与序列序列化为一份 JSON（可下载备份、分享给他人）。
- **导入**：支持三种来源——**粘贴 JSON**、**选择本地文件**、**填写远程地址（URL）**；解析后预览新增 / 跳过 / 冲突项，再确认导入。

下面重点讲：如何**手写**一份可导入的 JSON。

#### 3.1 JSON 结构

```json
{
  "$schema": "text-batch-processor-pack",
  "version": 1,
  "actions": [
    {
      "name": "动作显示名",
      "code": "return text.toLowerCase();",
      "category": "格式化",
      "favorite": false
    }
  ],
  "sequences": [
    {
      "name": "序列显示名",
      "category": "清理",
      "favorite": true,
      "steps": [
        { "actionName": "动作显示名" }
      ]
    }
  ]
}
```

字段说明：
- **`$schema`** / **`version`**（可选）：标记数据包格式，当前固定 `"text-batch-processor-pack"` 与 `1`。
- **`actions[]`**：动作数组。
  - `name`（必填，字符串）：动作名，也是序列引用它的依据。
  - `code`（必填，字符串）：JS 函数体，必须 `return` 字符串；可用 `text` 变量。
  - `category`（可选，字符串）：分组；空字符串或 `"未分类"` 视为未分类。
  - `favorite`（可选，布尔）：是否常用。
- **`sequences[]`**：序列数组。
  - `name`（必填，字符串）：序列名。
  - `category` / `favorite`（可选）：同动作。
  - `steps[]`：**步骤列表**，每个步骤用 **`actionName`** 引用包内某个动作的 `name`（**不是 id**）。导入时会重新生成 id 并自动映射，因此同一份 JSON 在不同 vault 间可移植。

> 解析是**宽松容错**的：缺字段会按默认值补齐，非法项会被跳过并提示，不会整包失败。

#### 3.2 手写要点（让 AI / 人都好读）

- JSON 不支持注释，请用**清晰的 `name`** 表达意图，把逻辑留在 `code`。
- 序列步骤用动作**名**关联，必须保证 `steps[].actionName` 与某个 `actions[].name` **完全一致**（含大小写、空格）。
- 一份 JSON 可以只有 `actions`、只有 `sequences`，或两者皆有。
- `code` 是 JSON 字符串：**正则里的 `\` 要写成 `\\`，换行 `\n` 同理**。例如 JSON 里应写 `"return text.replace(/^#+\\s+/gm, '');"`（插件解析后得到 `text.replace(/^#+\s+/gm, '')`）。
- 想多端同步或分发给他人：把文件放到任意可访问 URL（如 GitHub raw），导入时填地址即可一键拉取。

#### 3.3 如何导入

1. 设置 → 第三方插件 → 文本批处理 → 选项。
2. 找到「导入 / 导出」区，点 **导入配置**。
3. 选一种来源：粘贴 JSON / 选本地 `.json` 文件 / 填远程地址（默认预填官方示范库）。
4. 点「解析并预览」，确认新增 / 跳过 / 冲突项。
5. 选冲突策略后「确认导入」：
   - 同名不同内容：「重命名旧的」（默认，双方都在）/「覆盖旧的」。
   - 同内容不同名：「保留原名称」（默认，跳过重复）/「用新名称覆盖」。

#### 3.4 完整可导入示例

下面这份 JSON 可直接粘贴导入（两个动作 + 一个序列，演示流水线顺序）：

```json
{
  "$schema": "text-batch-processor-pack",
  "version": 1,
  "actions": [
    {
      "name": "全部转为小写",
      "code": "return text.toLowerCase();",
      "category": "格式化",
      "favorite": false
    },
    {
      "name": "反转字符顺序",
      "code": "return text.split('').reverse().join('');",
      "category": "格式化",
      "favorite": false
    }
  ],
  "sequences": [
    {
      "name": "先小写再反转",
      "category": "演示",
      "favorite": true,
      "steps": [
        { "actionName": "全部转为小写" },
        { "actionName": "反转字符顺序" }
      ]
    }
  ]
}
```
